## 调用协议

```http
POST /api/capabilities/{name}
Content-Type: application/json

{
  "client_invocation_id": "chat-7f3a-turn-12:mindmap:1",
  "query": "麻黄和桂枝有什么区别",
  "params": { "depth": 3, "structure": "auto" },
  "context": { "conversation_id": "c_9f1" }
}
```

`params` 可以省略——顶层字段与 `params` 里的同名字段等价，顶层优先。

- `client_invocation_id` 幂等键：**同样的键 + 同样的参数**只受理一次，重放返回同一个 `task_id`，响应里 `replayed: true`。
- 同一个键配了不同参数是调用方的 bug，返回 409 `capability.idempotency_mismatch`。
- `job` 类返回 202 + `task_id` + `stream_url`；`query` / `command` 类同步 200。

轮询兜底与取消：

```http
GET  /api/capability-invocations/{invocation_id}
POST /api/capability-invocations/{invocation_id}/cancel
```

## 能力

### doc.generate

**生成文稿** — 把一句写作诉求做成一份分节、标了引文、体裁先确认的文稿

- 版本：`1.0`　类型：提交即返回　幂等：是
- 耗时：通常 15~60 秒，取决于篇幅；无 key 时 3 秒内
- 成本：无模型 key 时零调用；有 key 时按节生成
- 依赖：登录用户、本地中药学知识库（可缺，缺则全部标为模型补充）

**什么时候该用**

- 要一篇文字成品：如「写一篇人参的用法与禁忌」
- 要讲义/学习计划/操作指南/对比分析：如「整理一份解表药复习提纲」
- 要长文而不是几句话：如「综述一下十八反的研究现状」

**什么时候别用**

- 只要一段口头解释：直接回答更省时间，不必落一份文稿
- 要一张关系图：用 mindmap.generate——文稿不做树
- 要讲给别人听、要分页：用 ppt.generate——文稿不做页
- 要改已有文稿的某一节：那是编辑器的事，不要重新生成整篇

**产物**

- 类型：`doc`
- 打开地址：`/resources/{resource_id}`（done 后可填）

**工序**

拟定方案 → 定体例 → 落笔成稿 → 核对引文 → 封存入库

**流事件**：`step_start`、`step_done`、`plan`、`design`、`pause`、`block`、`verify`、`done`、`error`

**可预期失败**

| 码 | HTTP | 说明 |
|---|---|---|
| `mindmap.topic_empty` | 422 | 没有说要写什么 |
| `capability.invalid_input` | 422 | 参数越界 |
| `capability.not_found` | 404 | 知识节点不存在 |
| `capability.idempotency_mismatch` | 409 | 同一请求号配了不同参数 |

**副作用**

- 新建一条炼制任务
- 完成后在用户资源库落一份文稿

**例子**

- 「写一篇人参的用法与禁忌」
- 「整理一份解表药复习提纲」
- 「对比麻黄与桂枝的临床应用」

### kb.search

**检索本地中药学知识库** — 查某个词在不在本地教材语料里，并给出可引用的原文条目

- 版本：`1.0`　类型：同步查询　幂等：否
- 耗时：毫秒级
- 成本：纯本地检索，无模型调用
- 依赖：本地中药学知识库

**什么时候该用**

- 要确认某个说法有没有教材依据：如「教材里有说桂枝反藜芦吗」
- 要一组可引用的原文：如「找几段麻黄性味的原文」
- 生成前先探底：看这次主题能不能落到教材上

**什么时候别用**

- 要关系与配伍：用 kg.ask / kg.compare——检索只给文本段落
- 要成图或成文：用 mindmap.generate / doc.generate

**可预期失败**

| 码 | HTTP | 说明 |
|---|---|---|
| `mindmap.topic_empty` | 422 | 没有说要查什么 |

**例子**

- 「教材里有说桂枝反藜芦吗」
- 「找几段麻黄性味的原文」

### kg.ask

**沿图谱查关系** — 查两个实体之间的教材明文关系，或单味药的主治与组成

- 版本：`1.0`　类型：同步查询　幂等：否
- 耗时：10~200 毫秒
- 成本：不调模型
- 依赖：登录用户、本地中药学知识图谱

**什么时候该用**

- 问「为什么」：如「麻黄和桂枝为什么常一起用」
- 问「能不能一起用」：如「人参和藜芦能一起用吗」
- 问某味药治哪些证、某个方由哪些药组成：如「麻黄能治哪些证」

**什么时候别用**

- 只问单味药的性味、功效、用量：如「麻黄的功效是什么」——普通检索更全
- 问两味药的区别：如「麻黄和桂枝有什么区别」——用 compare
- 问教材没收录的药：如「紫河车有什么功效」——先确认实体存在

**产物**

- 类型：`facts`

### mindmap.generate

**生成思维导图** — 把一句中药学主题或问题，长成一张可编辑、标了依据来源的导图

- 版本：`2.0`　类型：提交即返回　幂等：是
- 耗时：通常 6~20 秒；无 key 时 2 秒内
- 成本：无模型 key 时零调用；有 key 时一次结构化生成
- 依赖：登录用户、本地中药学知识库

**什么时候该用**

- 要一张图看全某个主题：如「画一张麻黄的知识导图」
- 要看清一类药的构成：如「解表药的分类」
- 要摆开两味药的差异：如「麻黄和桂枝有什么区别」
- 要从功效倒查药：如「哪些药能安神」
- 要梳理硬性配伍禁忌：如「十八反有哪些」

**什么时候别用**

- 只问一句话的答案：如「麻黄性味是什么」——直接答比出图快
- 问教材里没有的方药：如「紫河车有什么功效」——会整棵树退化成推断，不如直说查不到
- 要改已有导图的结构或配色：用 mindmap.present，不要重新生成

**产物**

- 类型：`mindmap`
- 打开地址：`/mindmap?resource={resource_id}`（done 后可填）

### path.focus

**在地图上定位** — 把「我想学麻黄」「合谷在哪」定位到地图上的那一关，并给出可点的跳转

- 版本：`1.0`　类型：同步查询　幂等：否
- 耗时：通常 < 50 毫秒
- 成本：无模型调用
- 依赖：登录用户、知识树

**什么时候该用**

- 用户问某个知识点在地图/经脉上的位置：如「合谷在哪」「麻黄在第几关」
- 用户说想学某个具体内容：如「我想学麻黄」「带我去看清热药」

**什么时候别用**

- 要解释知识本身：用 kg.lookup / kg.ask，定位不等于讲解
- 要规划整条路线：用 plan.create
- 说法太泛（「我想学中医」）：先问清是哪一块，别硬定位

**可预期失败**

| 码 | HTTP | 说明 |
|---|---|---|
| `capability.invalid_input` | 422 | 没说要找什么 |

**例子**

- 「合谷在哪」
- 「我想学麻黄」
- 「带我去看清热药」

### plan.create

**排一份学习路线** — 按知识依赖与可用时间排出先学什么、后学什么；不是查资料，是排顺序

- 版本：`1.1`　类型：同步查询　幂等：否
- 耗时：通常 5~20 秒
- 成本：有模型 key 时一次模型调用；无 key 时按依赖与掌握度直接排
- 依赖：登录用户、知识树

**什么时候该用**

- 用户要一份学习计划：如「帮我做个计划，我想学习中药学，两年后考研」
- 问该从哪开始：如「我基础差，先把哪几块补上」
- 给了期限：如「三个月内过一遍方剂」

**什么时候别用**

- 只问某个知识点：用 kg_* 直接答
- 要看自己现在什么水平：用 profile.view——那是画像，不是路线
- 要一份能拿走的材料：用 doc.generate / mindmap.generate

**产物**

- 类型：`path`
- 打开地址：`/path?focus={resource_id}`（done 后可填）

**可预期失败**

| 码 | HTTP | 说明 |
|---|---|---|
| `capability.invalid_input` | 422 | 时间预算不合法 |
| `capability.conflict` | 409 | 规划没能完成 |

**副作用**

- 存一版 L1 路径计划
- 展开第一个阶段并存一版 L2 计划
- 为计划里的知识点初始化学习状态

**例子**

- 「帮我做个计划，我想学习中药学，两年后考研」
- 「三个月内过一遍方剂，怎么安排」

### plan.present

### ppt.generate

**生成幻灯片** — 把一句讲授需求做成一份可编辑、标了依据、设计先确认的幻灯

- 版本：`1.0`　类型：提交即返回　幂等：是
- 耗时：通常 8~25 秒；无 key 时 3 秒内
- 成本：无模型 key 时零调用；有 key 时一次结构化生成
- 依赖：登录用户、本地中药学知识库（可缺，缺则全部标为模型补充）

**什么时候该用**

- 要做一份讲稿：如「做一份人参的讲稿，12 页」
- 要给课堂/规培/科普准备演示：如「给规培医师讲十八反」
- 已有资源要重做一版：先用 ppt.generate 重新起稿，再在编辑器里改

**什么时候别用**

- 只要一段文字说明：用 doc.generate（或直接回答），出幻灯是杀鸡用牛刀
- 要一张关系图：用 mindmap.generate——导图不做页，幻灯不做树
- 要改已有幻灯的某一页：那是编辑器的事，不要重新生成整份

**产物**

- 类型：`ppt`
- 打开地址：`/ppt?resource={resource_id}`（done 后可填）

**工序**

拟定方案 → 设计版式 → 选取素材 → 逐页成稿 → 校验依据 → 封存入库

**流事件**：`step_start`、`step_done`、`plan`、`design`、`pause`、`slot_resolution`、`slide`、`deck_verify`、`done`、`error`

**可预期失败**

| 码 | HTTP | 说明 |
|---|---|---|
| `mindmap.topic_empty` | 422 | 没有说要讲什么 |
| `capability.invalid_input` | 422 | 参数越界 |
| `capability.not_found` | 404 | 知识节点不存在 |
| `capability.idempotency_mismatch` | 409 | 同一请求号配了不同参数 |

**副作用**

- 新建一条炼制任务
- 完成后在用户资源库落一份幻灯

**例子**

- 「做一份人参的讲稿，12 页」
- 「给规培医师讲十八反」
- 「中医科普：阴阳」

### profile.view

**查看学习画像** — 读出七个维度的分数、置信度与最弱项，用于「我哪块最弱」这类问题

- 版本：`1.0`　类型：同步查询　幂等：否
- 耗时：毫秒级
- 成本：纯本地读取，无模型调用
- 依赖：登录用户

**什么时候该用**

- 问自己的学习状况：如「我的画像里哪块最弱」
- 问某个维度：如「我的知识基础怎么样」
- 要看依据：如「你凭什么说我记不牢」

**什么时候别用**

- 要学习计划：那是路径规划的活，不是画像
- 问教材知识：用 kg_* 六能力

**可预期失败**

| 码 | HTTP | 说明 |
|---|---|---|
| `capability.invalid_input` | 422 | 维度名不认识 |

**例子**

- 「我的画像里哪块最弱」
- 「我的知识基础怎么样」

### quiz.generate

**生成试卷** — 按考点出一份可练的卷子：先给卷式与考点，确认后拟题设错

- 版本：`1.0`　类型：提交即返回　幂等：是
- 耗时：通常 10~40 秒；无 key 时 3 秒内
- 成本：无模型 key 时零调用；有 key 时按题量生成
- 依赖：登录用户、本地中药学知识库（可缺，缺则题目按通用知识出，并在 verify 里说明）

**什么时候该用**

- 要一份练习卷：如「出一份解表药的卷子，八道题」
- 要错题式辨析：如「考考我麻黄和桂枝的区别」
- 要配伍禁忌的判断练习：如「出几道十八反的配伍题」

**什么时候别用**

- 只想问一个答案：直接回答，不必出卷
- 要知识结构：用 mindmap.generate
- 要讲解材料：用 doc.generate——卷子不给解释

**产物**

- 类型：`quiz`
- 打开地址：`/resources/{resource_id}`（done 后可填）

**工序**

拟定方案 → 定卷式 → 拟题设错 → 核对答案 → 封存入库

**流事件**：`step_start`、`step_done`、`plan`、`design`、`pause`、`items_verify`、`done`、`error`

**可预期失败**

| 码 | HTTP | 说明 |
|---|---|---|
| `mindmap.topic_empty` | 422 | 没有说考什么 |
| `capability.invalid_input` | 422 | 参数越界 |
| `capability.not_found` | 404 | 知识节点不存在 |
| `capability.idempotency_mismatch` | 409 | 同一请求号配了不同参数 |

**副作用**

- 新建一条炼制任务
- 完成后在用户资源库落一份试卷

**例子**

- 「出一份解表药的卷子，八道题」
- 「考考我麻黄和桂枝的区别」
- 「出五道十八反配伍题」

### resource.generate

**生成其它学习资源（未接）** — 文档、试卷、故事、幻灯的统一入口；本期只占位，调用返回 501

- 版本：`0.1`　类型：提交即返回　幂等：是

**什么时候该用**

- 需要文档/试卷/故事，且调用方愿意等它接完

**什么时候别用**

- 要导图：用 mindmap.generate，那条已经通了
- 要幻灯：用 ppt.generate，那条也已经通了
- 要文稿：用 doc.generate，那条也已经通了
- 现在就要产物：直接调既有的 /api/resource/tasks 端点

**产物**

- 类型：`resource`
- 打开地址：`/resources/{resource_id}`（done 后可填）

**可预期失败**

| 码 | HTTP | 说明 |
|---|---|---|
| `capability.not_implemented` | 501 | 这条契约还没接 |

> 等 quiz/story 升到带依据的管线后接上，届时去掉 501；ppt 与 doc 已由各自能力接管。

### story.generate

**生成漫剧分镜** — 把一味药或一段医案编成一出短剧：先定场次与角色，确认后写台词

- 版本：`1.0`　类型：提交即返回　幂等：是
- 耗时：通常 15~45 秒；无 key 时 3 秒内
- 成本：无模型 key 时零调用；有 key 时按场次生成
- 依赖：登录用户、本地中药学知识库（可缺，缺则按通用知识编，并在 verify 里说明）

**什么时候该用**

- 要把知识点讲成故事：如「把麻黄汤证讲成一出短剧」
- 要有人物与冲突的素材：如「编一个学徒用错桂枝的故事」

**什么时候别用**

- 要严格的知识结构：用 mindmap.generate——故事不为覆盖率负责
- 要引用逐条可核的讲义：用 doc.generate
- 要题目：用 quiz.generate

**产物**

- 类型：`story`
- 打开地址：`/resources/{resource_id}`（done 后可填）

**工序**

拟定方案 → 定场次 → 编排药语 → 校验医据 → 封存入库

**流事件**：`step_start`、`step_done`、`plan`、`design`、`pause`、`items_verify`、`done`、`error`

**可预期失败**

| 码 | HTTP | 说明 |
|---|---|---|
| `mindmap.topic_empty` | 422 | 没有说讲什么 |
| `capability.invalid_input` | 422 | 参数越界 |
| `capability.not_found` | 404 | 知识节点不存在 |
| `capability.idempotency_mismatch` | 409 | 同一请求号配了不同参数 |

**副作用**

- 新建一条炼制任务
- 完成后在用户资源库落一份漫剧分镜

**例子**

- 「把麻黄汤证讲成一出短剧」
- 「编一个学徒误用十八反的故事」
- 「四场讲清桂枝汤的配伍」
