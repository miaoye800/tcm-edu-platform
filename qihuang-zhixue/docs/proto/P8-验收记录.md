## 2. 为什么只传 `node_id`，不传描述文本

第一版把节点的 `description` 整段塞进 system。后果：模型顺着那段把教材念一遍——
用户这次问的可能是完全另一件事，却收到一大段他已经看过的正文。

现在的 `_node_hint()` 只给**结构**：

```
中药学 · 解表药 · 发散风寒药 · 知识点「麻黄」 · 穴位 中府（LU 1） · 目标掌握度 0.82
```

够模型判断"该举哪类例子、这个点学到哪了"，又不会被当成话题本身。

## 3. `path.focus` 的六步匹配

按确定性从强到弱，命中即返回：

| 步 | 匹配方式 | 置信度 |
| --- | --- | --- |
| 1 | `node_id` 精确 | 0.99 |
| 2 | 节点名精确 | 0.95 |
| 3 | 别名（教材异名） | 0.90 |
| 4 | 穴位名 / 穴位代号（`LU1`、`中府`） | 0.85 |
| 5 | 最长包含匹配 | 0.70 |
| 6 | 都不中 → 候选列表（最多 3 个） | 失败 |

第 5 步取**最长**而不是第一个：「清热药」与「清热燥湿」都包含「清热」，
用户说「清热」多半指大类，说全称才指细分。

第 6 步不能只说"没找到"：用户体验是"我问了合谷，它说不认识"。给候选，
每个候选都带一个可直接点的 `ui_actions`。

## 4. 深链落地必须**选中那一条刻度**（本轮修的缺陷）

`/path?focus=d01.s1.p1` 进 L2 后，第一版右侧一列 16 条刻度**一条都没选中**：
用户还得自己找哪一行是「麻黄」。深链的意义就是替他做掉这一步。

根因：`selectByNode()` 调了 `selectAcupoint()`，而后者把 `activeTickId` 清成 `null`
（那是"从 L2 退回 L1"该做的事）。

```ts
// 改前：飞过去，但刻度归零
selectAcupoint(section.acupoint_id)
activeSectionId.value = section.id
activeTickId.value = nodeId

// 改后：只补相机，选中归属写死
selectedId.value = section.acupoint_id
activeSectionId.value = section.id
activeTickId.value = nodeId
```

另外补了一道：目录晚到时 `selectByNode` 只排待办，`loadAtlas` 消费完要**再同步一次
地址栏**——否则刷新 `?focus=` 深链后，右侧选中的是 A，地址栏却是空。

## 5. 地址栏：`replace` 不是 `push`

位置变化是"我在看哪一条"，不是一次页面跳转。用 `push` 会让浏览器后退键变成
"退到上一条知识点"，退十几下才出得去。

```ts
const syncFocus = (nodeId: string) => {
  if (route.query.focus === nodeId) return
  void router.replace({ query: { ...route.query, focus: nodeId } })
}
```

那道 `if` 是防抖闸门：点刻度 → emit → 父级 replace → watch 回传 focus →
`selectByNode` → 又有 emit。少这道闸门就是"点一下抖两下"。
