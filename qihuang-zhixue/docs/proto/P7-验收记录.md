## 2. 这一轮逮到的三个缺陷（都是"看起来成功了"的那种）

呈现是 P7 唯一会**落一份长期资产**的动作。它出的错都不会报异常，只会悄悄导出一份
不完整的东西，用户打开才发现不对。实拍连跑四轮，每轮揪一个：

| # | 现象 | 根因 | 修法 |
| --- | --- | --- | --- |
| 1 | 确认 81 个点，导图只有 **2 个** | 确认明细返回的 `version` 是 `versions[-1]`，也就是**最后一个域的 l2 行号**；handler 拿它当"路线版本号"去取 payload，取到的是那一章 | 新增 `_is_route_version()`：`l1` 或草稿才算整条路线。整条路线不能读 l1 自己的 `nodes`（按设计恒为空），要走 `_nodes_from_confirmed_route()` |
| 2 | 修完 1，导出变 **133 个**，而确认的是 85 个 | `_nodes_from_active()` 读的是 `current_path`，那是**按域累积**的地图视图，会把历史上确认过的所有域都并进来 | 导出取"同一批 active 行"（`confirmed_at` 相同），地图继续用累积视图。两者语义不同，不能共用一个函数 |
| 3 | 复测"只产 1 份"时又新建了一份 | 幂等键是 `f"plan_{version}_{kind}"`，而调用方不传 `version` 时后端自己算"最近一批"——两次请求之间可能已经前进了一版 | 响应体回 `plan_version`（实际导出的那一版）；调用方复述时带上它 |

第 3 条还有个连带修：`capture-plan-wizard.mjs` 原来从「第 N 版路线已生效」那句话里抠版号，
那是最后一条 l2 的行号，拿它复测等于换了一份东西再问。改成读响应里的 `plan_version`。

## 3. 「呈现」不是「生成」

`present_plan()` **不调模型、不重新谋篇**，只把既定结构翻译成两种可读形态：

```
导图：学科 → 章 → 小节 → 知识点（叶子带 meta.node_id）
文稿：标题 → 阶段 → 知识点列表项（block.meta.node_id）
```

复用 `mindmap.generate` / `doc.generate` 都会出事：前者自己长树、不知道 `node_id`，
节点点不回地图；后者命中「学习计划」后会走自己的七节骨架，把用户确认过的取舍再猜一遍。

## 4. 体裁选择的三个信号

```python
prefer in ("mindmap", "doc")            → 用户指定
profile.resource_preference.confidence ≥ 0.5
  label ∈ {知识图谱, 思维导图} or 学习风格=视觉型 → mindmap
  label ∈ {教材精读, 讲义}                      → doc
len(nodes) > 24 or len(stages) > 3      → doc（手机上导图只读成缩略图）
否则                                     → mindmap
```

不交给模型：同一个人两次问同一件事拿到不同格式，用户第一反应是"系统不稳定"。

---

## 5. 只读快照：改它不改地图

产物落在 `user_resource` 里（`meta.plan_present=true`, `plan_version`），与地图没有反向通道。
导图的编辑能力（拖节点、换主题）在 `/mindmap` 里照常可用，但**保存只改这份快照**。

这是刻意的：计划是"我确认过的结构"，用户在导图上挪一个分支不该让下周的学习路线改道。
要改路线回 `/path` 走向导。

## 6. 前端：确认页里那一块

```
④ 确认
   路线已经生效。地图上对应的穴位会依次点亮。
   第 98 版路线已生效，共 19 个知识点。
   ┌ 顺手导了一份导图：我的学习路线
   │ 你的资源偏好是「汤头歌诀」（置信度 0.78） · 19 个知识点
   │ [打开看一眼]
   └
                              [去地图上看]
```

- **主按钮仍是「去地图上看」**，导出是旁路（左侧青色竖线 + 浅底），不与主操作抢权重。
- **只导一次**：不提供「换个格式再看」的二次入口——那会让资源库堆出一串内容相同的快照。
- **导出失败不回滚确认**：路线已经生效了，此时报失败会让用户以为白确认一次。降级成一行说明。
