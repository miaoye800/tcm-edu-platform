## 2. 帧率：先分清楚在测什么

三种环境差别巨大，混在一起写等于没写：

| 环境 / 态 | 档位 | fps | 最差帧 | draw calls | 面数 | 说明 |
| --- | --- | --- | --- | --- | --- | --- |
| AMD Radeon 780M（集显，真 GPU）· L0 全身 | desktop | **62.5** | 59.2 | 46 | 288 206 | vsync 封顶；bloom=half-float |
| 同上 · L2 近景 | desktop | 59.7 | 59.5 | 23 | 352 064 | 视锥剔除后 draw call 反而少 |
| 同上 · 打开骨骼层 | desktop | 57.6 | **29.9** | 51 | 419 060 | 最差帧是骨骼几何上传那一帧（128k 面一次性上传） |
| 同上 + iPhone 13 视口 + coarse pointer | mobile | **60.0** | 56.8 | 32 | 288 192 | bloom 自动关（配置档位） |
| 同上 + `Emulation.setCPUThrottlingRate(4)` | mobile | **60.0** | 56.8 | 32 | 288 192 | 4 倍降频仍顶到 vsync |
| headless + ANGLE/SwiftShader 软件光栅 | desktop | 5–6 | 5 | 46 | 288 206 | **不作数**：CPU 模拟 GPU，只说明"画面是对的" |

> 截图上的帧率数字会比脚本打印的小一个量级：`page.screenshot()` 本身会让主线程停住，
> HUD 上那行"7 fps / 最差帧 3 fps"是截图动作自己造成的。以脚本打印的 `stats` 为准。

口径三件事（P0 §3 定的，P3 照抄）：

- `renderer.info.autoReset = false` + 每帧 `info.reset()`。接上 EffectComposer 后不 reset，
  读到的是最后一个全屏 pass 的 `1 tris / 1 calls`。
- fps = `frames / (now - windowStart)`，不用 `1/dt` 累加。
- 单帧 > 2 s 不计入最差帧（切标签页回来那一下不是卡顿）。

手机档位的降级动作只有两条：关 bloom（唯一的吃满屏像素项）、`pixel_ratio_cap` 2 → 1.5。
肌肉层留着（它才是"看得懂"的那层），骨骼层在 desktop/mobile 两档都默认关。

> ⚠️ **真机未测**。上面的 60 fps 来自同架构集显 + Chromium 手机仿真，能证明"代码路径不卡"，
> 不能替代 iOS Safari / Android Chrome 的实测。真机跑法：
> `node scripts/capture-meridian-scene.mjs <真机可访问地址>`，脚本会把 fps / 最差帧 / draw calls 打出来。

## 3. 整屏透明：一次教科书级的 NaN 传播

### 3.1 现象

开了 bloom，整块 canvas 读回 `rgba(0,0,0,0)`——**不是黑色，是透明**。关掉 bloom 立刻正常。
`gl.getError()` 返回 0，`checkFramebufferStatus` 报 `FRAMEBUFFER_COMPLETE`，console 一条报错都没有。

### 3.2 定位过程

1. 逐 pass 采样：`RenderPass + OutputPass` → 正常；中间插 `UnrealBloomPass` → 透明。
2. 换一条全 RGBA8 的 bloom（构造后、上传前改 `texture.type`）→ **正常**。
   线索：RGBA8 写入时会把 NaN 压成 0，所以它"免疫"。
3. 逐对象二分：把 `scene.children` 全隐藏后逐个放回，**肌肉层（MeshStandardMaterial）一出现就翻车**。
4. 数法线：肌肉 43 997 个顶点里有 **319 个零长度法线**。`MeshStandardMaterial` 对它做
   `normalize` 得到 NaN，NaN 写进半浮点 RT，模糊链的加性混合把它摊到整帧，
   `OutputPass` 输出 NaN → 画布被清成透明。

### 3.3 修法（三层，缺一不可）

| 层 | 文件 | 改动 |
| --- | --- | --- |
| 打包端（根因） | `app/meridian/asset.py` | `vertex_normals()` 对退化顶点给"由形体中心指向该点"的兜底方向，不再留 `(0,0,0)`；新单测 `test_vertex_normals_never_degenerate` 守死 |
| 加载端（兜底） | `BodyMesh.vue` | `sanitizeNormals()` 把 `(0,0,0)` 换成 `(0,1,0)`；坏数据不该等到渲染才爆 |
| 着色器（防扰动） | `BodyMesh.vue` | 法线扰动后 `length() > 1e-5 ? perturbed/pl : normal`，不再裸 `normalize` |

重打包后三层的零法线数：skin 0 / muscle 0 / skeleton 0。

### 3.4 顺带留下的护栏：三级降级梯子

半浮点链在**别的** GL 实现上仍可能静默失败（我们只能证明"这一台上不是半浮点的问题"），
所以 `useMeridianScene.ts` 里留了一条**用真渲染自检的**梯子：

```
半浮点 bloom → 渲一帧读像素 → 通过则用，不通过 →
全 RGBA8 bloom → 再读一次 → 通过则用，不通过 →
关掉后期链（辉光交给穴位光晕与经脉流光自己画，它们本来就有）
```

两个细节：

- **读像素是唯一手段**。`checkFramebufferStatus` 与 `gl.getError()` 对这种失败都是"一切正常"。
- **自检要做两次**。开场时人还没加载，只有背景，半浮点链是好的——第一版自检因此放行，
  真内容一进来就黑。所以第一帧 `draw calls > 4` 之后再验一次，挂了就当场降级。
- 实际启用的档位暴露在 `window.__meridianRuntime.bloomMode`（`half-float | rgba8 | off`），
  验收脚本据此判断"这台跑的到底是什么"。

## 4. 这轮实拍改出来的六件事

### 4.1 L0 / L1 / L2 的状态机（计划原始要求）

| 态 | 相机距离 / fov | 视高 | 右侧 | 实测 |
| --- | --- | --- | --- | --- |
| L0 全身 | 3.10 m / 34° | 1.90 m | 无 | ✅ 不画刻度、不挂穴名 |
| L1 章节 | 1.25 m / 30° | 0.67 m | `TickBand`（该穴挂的小节） | ✅ 点"中府" → `view=chapter`、刻度带出现、抽屉显示"community 坐标 · 已排入路线" |
| L2 穴位 | 0.62 m / 24° | 0.26 m | `TickPoint`（逐点刻度可点） | ✅ 点"发散风寒药" → `view=acupoint`、逐点刻度列出麻黄/桂枝/紫苏叶… |

**机位是实拍改出来的**：原配置 `chapter 0.62 / acupoint 0.34`，视高只有 0.33 m / 0.14 m——
屏幕上是"一块肌腹"，既看不出这一段是胸前还是后背，也看不出旁边还有云门。收到 `1.25 / 0.62`
之后：章节能认出部位，穴位能看见相邻穴与经脉走向。

`back` 逐级退回；`Esc` 在无障碍列表里等价于 `back`。

### 4.2 舞台是"恒定的深色岛"，HUD 不能吃主题前景色

浅色主题下 `--qh-fg-muted` 是深灰、`--qh-surface` 是米白。压在深色画布上的结果是：
整排图层勾选框**只剩四个绿方块**（文字隐形），面板则是"米白条盖住人体"。

修法：在 `.meridian-scene` 上把深色侧变量钉死，HUD 子组件一律继承。**坑在别名的求值时机**：
`--qh-color-night: var(--qh-bg)` 是在 `:root` 上求值的，在舞台子树里改 `--qh-bg` 一点用都没有，
必须直接钉 `--qh-color-night` / `--qh-color-night-soft` 本身。第一版只钉了底层变量，
结果变成"米白面板 + 浅色文字"，比原来更糟——这条写进注释了。

### 4.3 HUD 不许互相压

| 症状 | 原因 | 修法 |
| --- | --- | --- |
| 图例盖掉底部路线条最左边的芯片 | 图例 `bottom:56` vs 路线条 `bottom:20` 高约 44 | 图例抬到 `bottom:74` |
| 键盘浏览入口与路线条同角 | 都在 `bottom:16 / left:16` | 入口改到右下，路线条右边界留 190px |
| L2 时刻度带表头被裁一半 | `.hud-right` `top:76` 撞上学科胶囊两行 | `.hud-right` `top:112` |
| 精度声明被卡片下缘切掉 | `bottom:2px` 贴边 + `overflow:hidden` | `bottom:6px` |
| L2 时详情抽屉被刻度列顶出可视区 | 16 条刻度 `flex: 0 0 auto` 把 452px 的列占满 | 刻度列 `max-height: 44%` 内部滚，抽屉 `flex: 1 1 auto` 拿剩余 |

右侧那一列是"刻度 + 正文"抢同一个高度，规则记死：**刻度最多 44%，剩下全给抽屉**。
抽屉才是点开知识点要读的东西；让它被刻度顶出去等于把学习正文藏了。

### 4.4 全身态不挂穴名

362 个穴名在 3 m 视距下必然在头面糊成一团——屏幕空间避让只能把它们推得更远，救不了密度。
改成 `labelsVisible = showLabels && view !== 'overview'`，全身态勾选框置灰并标"近景"。

### 4.5 手机窄屏

375 宽下"四角各一块面板"会把人体糊死。改成"顶部一行 + 底部抽屉"：学科胶囊单行横滑
（`:deep(.layer)` 必须 `flex: 0 0 auto`，否则"中医基础理论"被压成一列竖排字）、
图层开关只留三个（多一行就盖住脚背的至阴/太冲）、刻度带与详情走全宽抽屉占下半屏。

### 4.6 标签避让（验收项 2 的实现细节）

`CSS2DObject` 不参与深度测试，正面的穴名会"透过身体"浮在背面——所以每个标签记住穴位体表法线，
背向相机就隐身（`normal_cull 0.06`）。避让按屏幕 y 排序后逐个下推，X 向 74px 内、Y 向 19px 内算冲突。
左右同名穴只挂一侧，否则是双影。

## 5. 键盘与读屏（验收项 3）

canvas 对读屏是空白（读到的只有一堆 0），语义必须另建一层 `A11yMirror`：

- `role="list"` + 每个穴位一个按钮，`aria-label` 拼成"睛明 BL 1，足太阳膀胱经，挂…，待学"。
- `↑↓` 在列表内移动（首尾循环）、`Enter` 打开该穴、`Esc` 退回全身。
- `aria-live="polite"` 播报当前焦点穴位与完成度。
- canvas 本身 `aria-hidden="true"`。

实测（膀胱经，67 穴）：连按 `↓` 访问到 **67/67** 个不同条目，首条"睛明 BL 1 待学"、
末条"至阴 BL 67 未挂章节"，列表 `role="list"`。

## 6. 顺手修掉的旧账

`app/meridian/coords.py::skin_geometry()` 的体积校验还停在"只有 pos/normal/index 三段"的年代，
P2 给每份资产加了 `part` 段之后它一直在 `ValueError`。改法：按 `manifest` 的 `attributes`
逐段累加 + 4 字节对齐；`part_count` 是**不同分块的数量**，不是数组长度（长度按顶点数算）。

同时把 `tests/test_meridian_p2.py` 里 `.gz` 的断言改对：`.gz` 走传输层压缩，
`content-type` 是 `application/octet-stream` + `content-encoding: gzip`，
不是 `application/gzip`（后者表示"这个文件本身是个 gzip 包"，浏览器会另存而不会解压）。

## 8. 已知遗留（按优先级）

0. ~~`assign --backfill` 没跑~~ → **已核销**：`python -m app.meridian.assign --audit` 报
   **学习进度 51/51 能落到地图刻度**（`available` 35 / `current` 16）。现存进度不需要补分配，
   地图不会出现"学了 16 个但一片漆黑"。另：CLI 里**没有** `--backfill` 这个开关，
   计划 §12 那句话应改读为"上线前跑一次 `--audit` 确认 0 个悬空节点"。
1. **真机帧率未测**：只有同架构集显 + 手机仿真的数据。iOS Safari 的 CSS2D 合成开销是另一条账。
2. **全局侧栏在手机上不折叠**：占掉 108px，经脉舞台只剩 282px 宽。属全局布局（P0 范围），
   不是本页能修的。
3. 手机端学科胶囊会压到头顶那一小块（头面是穴位最密的区域）。
4. L1 态头面穴（睛明/攒竹/眉冲一带）标签仍偏挤——避让把它们推开后仍相邻。
5. 打开骨骼层那一帧有 128k 面一次性上传，最差帧掉到 29.9 fps（之后回到 57–60）。
   真要抹平就得分帧上传，收益不大，先记着。
6. 全站没有 favicon.ico，每个页面控制台都有 1 条 404，**不是回归**。
