## 1. 人体图：肌肉与骨骼两层下架

### 1.1 诊断

P9 只把肌肉调成「默认关」，HUD 上还留着三个图层开关，骨骼层更是从头到尾都在。
用户看到的「破碎」不是材质问题，是**几何本身不成立**：

- 肌肉层是 `voxel_cluster(cell=7.5 mm)` 的简化产物（`muscle.bin` 1.38 MB）。
  薄肌腹在这个格距下被磨穿，肌群之间没有筋膜填充，1.25 m 章节视距下就是
  一块块断开的红肉。补面补不回来——缺的是几何，不是面。
- 骨骼层与「看穴位在哪」无关：362 穴吸附在皮肤（FJ2810）三角形上，经脉折线走体表，
  **皮肤才是穴位这一概念的真实载体**。

## 2. 体表下体：从「平滑一下」改成「边界固定的调和填充」

### 2.1 评估

教学场景是课堂投屏 / 多人围观，**写实的男性外生殖器没有教学收益，却有明确的展示风险**
（含未成年人场景）。这不是"审美偏好"，是展示规范问题，必须处理。

三个候选：

| 方案 | 结论 |
| --- | --- |
| 加一条短裤遮挡 | **否**。任脉下腹三穴（曲骨 0.879 / 中极 0.917 / 关元 0.947）正好落在布料会盖住的位置，等于用展示规范换教学内容 |
| 保留原样、当医学插图 | **否**。用户已经明确指出展示场景不合适 |
| 只改体表几何 | **采用**。不新增图层、不挡穴位，可逆（一个 `enabled` 开关） |

### 2.2 第一版为什么失败

第一版是受限拉普拉斯（盒选种子 + 环带衰减 + 只重算受影响法线）。**实测不够用**：

| 指标 | 原始 | 拉普拉斯 26 次 |
| --- | --- | --- |
| 窗口内 z 峰值 | 0.1058 m | 0.0934 m |
| 侧面轮廓 | 一眼可辨 | **仍一眼可辨** |
| 副作用 | — | 腹股沟被一起熨平（`pelvis-laplacian-failed.png`） |

原因很清楚：拉普拉斯是**扩散**算子，它只能把突起摊成更矮更宽的突起。
突起是低频大尺度形状，不是噪声。

### 2.3 现在的算法

窗口内解 **Δp = 0，窗口边界环一个字节不动**——等价于在窗口上绷一张膜：

```
box:  |x| ≤ 0.055 / y ∈ [0.765, 0.872] / z ≥ 0.02      （1058 个顶点）
solve: Gauss–Seidel 超松弛 (relax 1.7) × 96 次
```

| 指标 | 原始 | 现在 |
| --- | --- | --- |
| 窗口内 z 峰值 | 0.1058 m | **0.0727 m**（退到阴阜平面，邻域体表 ≈0.074–0.078） |
| 受影响顶点（>1 mm） | — | 962 个 |
| 最大位移 | — | 7.47 cm（尖端） |
| 收敛 | — | 60 次即到 0.55 mm 以内，取 96 次留余量 |

边界固定是关键：膜与周围网格严格 C0 连续，**不会出现台阶**；窗口只罩住生殖器本身，
臀股、腹壁、腹股沟都不在窗口里，形状一点没动。

### 2.4 穴位与经脉线怎么办

- **穴位必须跟着体表走**。导出坐标（`x3d/y3d/z3d`）是原始几何上的点，几何一动它就浮空。
  用 `skin_tri` 在**改动前**的三角形上反解重心坐标，再套到改动后的三个顶点上：
  实测受影响的只有**会阴 CV1，位移 9.5 mm**；曲骨 / 急脉 / 冲门 / 长强的三角形落在边界环上，本来就没动。
- **经脉折线不用动**。窗口里 36 个折线点（ST/LR/CV）到新曲面的偏差最大 2.6 mm，在描边宽度内。
  而且任脉那一段本来就走在会阴侧（z≈0.037），比突起靠后 6 cm——它是**被突起挡住**，
  不是画在突起上，抹平后只会从"被挡住"变成"露出来"。

## 3. 规划器：让模型真正参与取舍

### 3.1 三个根因（不是"删中药"这一件事）

1. **用户原话从来没进过 prompt**。`planning_from_goal()` 只用关键词表把原话翻译成
   `breadth / pace / depth` 三个数字，模型看到的是「breadth=full」，看不到「已掌握中药学」。
2. **没有学科层**。90 个 domain 以 `b/z/d/f/a/n` 前缀散在库里，没有"学科"这个概念，
   模型只能逐章猜；而校验规则 `min_include` 又强制保住 60% 的章——整科跳过必然被拒。
3. **排序键是学科内章号**。`sort_hint` 是各科自己的章号（d01/f01/b01 都等于 1），
   六科之间没有先修边，`topo_sort` 于是把六科同章号排在一起：
   解表药（中药第 1 章）后面接方剂学第 1 章（方剂起源）。这就是用户说的"交织"。

### 3.2 学科层

新增 `backend/app/path/subjects.py`：六科由 domain id 前缀推导（`general` 特例归中药），
**不进库、纯函数**，`CANONICAL_ORDER = 中基 → 中诊 → 中药 → 方剂 → 针灸 → 内科`。
能力面、prompt、排序键、前端分组全部从这里取，不在各处再写一份映射。

### 3.3 取舍要有证据，且证据只能是真实信号

模型可以整科跳过、可以点名跳章跳点，但每条都要挂 `rationale.basis`：

- `request`（用户原话）——**豁免置信度门控**：用户自己说的话永远算数；
- `mastery`——按**知识点条数**算学科掌握比例（≥60%），不是按域节点算；
- `route`——已有路线里该科完成比例（≥60%）。

无据整科跳过 → `proposal.untrusted_mastery`，**降级成单条拒收**（学科仍留在范围内），
而不是整单拒。`request` 维度的理由不进 `_split_rationale` 的冲突检测——否则
冷启动画像置信度低会把用户原话一起杀掉。

### 3.4 排序键

```python
_node_sort_key = (order_key(subject_of(domain)), parent_sort, sort_hint, id)
```

学科块在前，块内仍是章序。同时 `verify_plan(assume_known=...)`：免修点不在路线里、
但前驱已满足时不再算"缺节点"，否则自动修复会把跳过的内容原样补回来。

### 3.5 真实调用结果（DeepSeek，`probe-p10`）

```

            符合由总到分的认知顺序
```

## 4. 「两个穴位相距很远」到底是什么问题

结论先说：**路线与穴位是"挂载"关系，不是"地图上的路径"。空间连续不是这套设计的目标，
而且不可能在"一具身体装全部学科"的前提下做到。** 下面是依据。

### 4.1 归经是语义的，不是几何的

`app/meridian/hints.py` 是一张手写的「章 → 经」表，注释就写着为什么：

```
"c08": "LU",  # 解表药：肺主皮毛，邪从表入、从表解
"c13": "TE",  # 利水渗湿药：三焦为决渎之官，通调水道
"c14": "GV",  # 温里药：督脉总督诸阳，温里即扶阳
```

于是同一门课的章会分布在十几条经上——学习顺序由学科与先修决定，穴位位置由
**章节语义**决定。两者天然不保证空间连续。

### 4.2 量化（当前库，293 章 / 362 穴）

相邻两章在体表的直线距离：

| 类别 | 次数 | 中位 | 最大 |
| --- | --- | --- | --- |
| 同一经内相邻 | 196 | **3.4 cm** | 26.1 cm |
| 换经（顺流注） | 91 | **52.7 cm** | 170.1 cm |
| 学科边界 | 5 | 27–84 cm | — |

>30 cm 的跳转 78 次，>60 cm 43 次，>100 cm 16 次。
复核脚本：`D:/Agent/tcm-edu-platform/.tmpverify/probe_route_geometry.py`

也就是说：**沿一条经往下走时是连续的（中位 3.4 cm），一跳就跳得远**。
用户观感里的"跳跃交织"来自三处，P10 只修掉了第一处（也是最刺眼的）：

1. 六科按章号交错（已修：学科成块，跨科跳转从"每章一次"降到 5 次）；
2. 一章一归经，学完解表药（肺/大肠经）接着清热药（胃/大肠经），必须换经——
   这是语义归经的必然结果；
3. 学科边界：每个学科占穴位序列的一段，换学科必然换段。

### 4.3 已做的缓解与没做的取舍

已做：

- 学科块把"远跳"集中到 5 个边界上，而不是散落在每一章之后；
- 章节态相机按经的 `view_bias`（前面/背面/侧面）切换，换经时是**镜头切过去**；
- 路线列表是主视图，人体图是定位辅助：点列表项 → 飞到该穴（`/path?focus=...` 深链）；
- 全身态用六学科色区分块，用户看到的是"六个色块分布在身上"，不是一条必须连续走完的线。

没做（产品级取舍，需要单独决策）：

- 让归经服从位置（牺牲"为什么解表药在肺经"这个教学锚点）；
- 每个学科一具身体（推翻 P9 定下的"一具身体装全部学科"）。

### 4.4 一项已知限制（记录，未擅自处理）

归经表只是**起点偏好**，不等于最终落点：六科共用一个游标，先分配的学科把经占满后，
后来的学科只能顺流注顺序溢到下一条经。当前库里**解表药落在大肠经（LI 3），
而 `hints.py` 写的是肺经**——因为肺经 11 穴被针灸学（手太阴肺经那一节）与内科学
（肺系病证）先占满了。

在临时库验证过：重跑 `python -m app.meridian.assign --all --source syllabus`
结果**完全一样**，所以这不是"表改了没重跑"的数据陈旧，而是分配算法的固有行为。
要严格保表，得把分配从"先到先得"改成"按章的偏好唯一性排序"或允许一章跨经，
会动到全部 293 节的落点，需要单独立项。
