# 知识图谱视觉规格（Graph Visual Spec）

> 本文件是图谱观感的**唯一验收基准**。所有数值来自对参考图
> `clipboard-2026-10-29T04-05-35-293Z-29f696fb.jpg`（881×1920）的像素采样，
> 采样脚本见文末。改图谱视觉前先改这里，再改代码。

## 0. 设计原则

一句话：**用明度表达层级，用留白表达呼吸，用极细线表达关系。**

三条铁律：

1. **不用色相区分节点类型**。四档层级是同一蓝色系的明度阶梯。色相只出现在
   筛选器、详情面板、以及「选中节点时的高亮边」。
2. **边只做暗示，不做强调**。1px 直线、单一颜色、无箭头、无虚线、无曲线。
3. **没有容器**。无边框、无圆角卡、无阴影、无网格。图谱漂浮在云雾渐变上。

模拟云雾。光斑位置：左上 20%/15%、右上 80%/10%、中下 50%/75%。

### 已实现值（`src/config/graph.ts`）

不照抄绝对像素：

|---|---|---|---|

## 3. 边

| 项 | 值 |
|---|---|
| 几何 | `THREE.LineSegments`，直线（不是贝塞尔曲线） |
| 颜色 | `#b9cbdd` |
| 透明度 | 正面 0.50，背面 0.18 |
| 粗细 | 1px（WebGL `linewidth` 恒为 1，不要试图改） |
| 箭头 | 无 |
| 虚线 | 无 |
| 选中态 | 与选中节点相连的边按 8 种关系色着色，opacity 0.85 |

**8 种关系色必须两两可分**。这条以前被违反过：`配伍禁忌` 用 `#b87d8b`、
`鉴别对照` 用 `#a47184`，两个灰玫瑰几乎同色，用户选中人参后根本分不清哪条是
禁忌边。现改为 `配伍禁忌 = #c05a52`（浅色）/ `#d98d86`（深色）——砖红，
1px 细线在云雾底上仍属「暗示」量级，但不会再被认成鉴别边。

另注：**默认态全图只有一种边色**（`#b9cbdd`），关系色只在选中节点时出现。
所以「没看到红色的禁忌线」先检查是否选中了节点，再怀疑颜色。

## 4. 景深（3D 可读性的核心）

参考图的立体感来自两条：近大远小、近浓远淡。3D 里分别对应：

| 效果 | 实现 |
|---|---|
| 近大远小 | 透视投影（`PerspectiveCamera` fov 28°，长焦，收缩温和） |
| 近浓远淡 | 每帧算节点沿**相机朝向**的深度，归一化后 `opacity = floor + (1 - floor) × t` |

### 深度必须沿相机朝向量，不能用径向法线

布局是压扁的椭球（`squashZ 0.28`），径向法线几乎躺在屏幕平面里，
`normal · toCamera` 恒 ≈ 0，所有节点会被压到同一个中间透明度。
实测后果：`#22459c` 渲染成 `#2c5fb8`，四档层级全糊。

正确做法（`applyDepth`）：

```
forward  = camera.getWorldDirection()
depth_i  = (p_i - camera.position) · forward
t_i      = 1 - (depth_i - min) / (max - min)     // 越近 t 越接近 1
```

| 参数 | 值 | 说明 |
|---|---|---|
| `minOpacity` | 0.56 | 最远处的下限 |
| `l1Floor` | 0.80 | 一跳是主体信息，只留很浅的景深 |
| `backLabelFactor` | 0.70 | 背面标签额外系数。取 0.42 时二跳背面实测 `#bfd2eb`，几乎不可读 |
| L0 例外 | 恒 1.0 | 中心节点是视觉锚点，吃景深就永远到不了 `#22459c` |
| L3 背面 | 0 | 只显圆点，不显字 |

标签渲染顺序：

- `depthTest: false`（文字永远可见，不被几何体遮挡）
- `renderOrder = 1000 + round(z × 0.05)`（近的盖住远的）

### 必须关掉色调映射

`renderer.toneMapping` 用 `NoToneMapping`。ACESFilmic 会把 token 颜色整体推偏
（实测 `#22459c` → `#003da9`，饱和度明显过高），而验收基准是 token 原色。

## 5. 布局

| 项 | 值 |
|---|---|
| 分层依据 | 从 `center_id` 做 BFS 算跳数 |
| 球壳半径 | L1 340 / L2 480 / L3 600 |
| 同层分布 | **Fibonacci 球面撒点** + 确定性抖动 + 椭球归一化空间内排斥松弛 36 次 |
| 确定性 | `pseudoRandom` 伪随机，刷新不跳 |
| 相机极角 | `elevation 0.47`（≈俯视 5.4°），phi = π × elevation |
| 椭球比例 | `squashY 0.46`、`squashZ 1.0`（x 与 z 等长） |
| 画布填充 | `fillX 0.92` / `fillY 0.86`，按真实投影**等比**缩放 |
| 默认方位 | 试 24 个角度，取「离中心最近的非中心节点」最远的那个 |

### 布局必须是真三维，不能是扁盘

这是「正面好看、一转就塌」的根因。旧实现只在 x/y 平面撒点、z 只做 ±0.28 抖动，
等价于一张扁平圆盘；相机绕 y 转到侧面时 x 变成景深方向，整盘压成一条竖线。

`x/z 等长 + 水平视角` 是唯一能同时满足「正面铺得宽」和「转起来不变形」的组合：

- 椭球 x/z 等长 → 任意方位角的水平延伸都是 `2R`，不会变窄
- 相机贴近水平（`elevation ≈ 0.5`）→ 世界 z 不会被投影到屏幕纵向

若俯视 18°（`elevation 0.40`），世界 z 会按 `sin18°` 混进屏幕纵向，
椭球的 x/z 对称被破坏，正面铺不宽、各方位角形状还各不相同。

### 排斥必须在椭球归一化空间里做

`relaxShell` 里先把 `y / squashY`、`z / squashZ` 再算距离。否则各向同性排斥会把
椭球推回球，压扁就白做了。

### 归一化必须是等比缩放

`fitStage` 三个轴用同一个 `k = min(fillX/reachX, fillY/reachY)`。
各轴独立缩放会破坏椭球比例：实测正面 `coverY` 被压到 0.415、侧面 0.603，
正面变成一条扁带，每个角度形状都不一样。等比缩放本身与方位角无关。

同时要在**多个方位角上取并集**（0°/45°/90°/135°）再算 `k`，
只按正面算的话，正面刚好、一转就顶出画布（实测背面「细辛」压到提示条上）。

### 归一化必须算上标签尺寸

节点是点，标签是面。宽标签（`发散风寒药` 5 字）在边缘一定会被裁。
`fitStage` 用 `camera.project()` 取 NDC 边界，再加标签自身的半宽/半高
（`worldWidth = font × scale × (字数 + 0.16)`），迭代 4 轮收敛。

### 默认方位角要挑

三维椭球上总会有节点落在相机轴线上，投影到画面正中、贴着中心词
（实测「小青龙汤」正好压在「麻黄」正下方 30px）。`rotateForBestFrontView`
试 24 个方位角，取「离中心最近的非中心节点」最远的那个。

实测结果（15 节点，1156×529 画布）：

| 方位 | coverX | coverY | 可见标签 |
|---|---|---|---|
| 正面 0° | 0.726 | 0.692 | 14/15 |
| 侧面 90° | 0.682 | 0.598 | 14/15 |
| 背面 180° | 0.621 | 0.675 | 14/15 |
| 侧面 270° | 0.652 | 0.656 | 14/15 |

四个角度的覆盖度差异在 ±8% 以内，且任何角度都没有节点越界。

## 5b. 标签去重叠（`cullOverlappingLabels`）

三维布局再均匀，投影到屏幕也一定有两个节点前后重叠的时候。每帧在屏幕空间做一次
贪心去重叠：

1. 把每个可见标签投影成屏幕矩形（世界尺寸按该节点深度换算成像素）
2. 按 `选中 > 中心 > 一跳 > 二跳 > 三跳`、同层近的优先排序
3. 依次占位，与已占位矩形冲突的标签 `opacity = 0`

被隐藏的只是**文字**，圆点仍在，节点依然可点、可悬停。实测各角度稳定保留 14/15。

> 优先级必须显式包含「选中」，否则聚焦一个二跳节点时，它可能被一个更高层级
> 但已经淡化的标签挤掉。

## 6. 交互

| 项 | 行为 |
|---|---|
| 拖拽 | 旋转视角（保留） |
| 滚轮 | 缩放 |
| 自动旋转 | 默认开，速度 **0.009**（原 0.018 的一半） |
| 拖动后 | 暂停自动旋转 3 秒 |
| 点击节点 | 选中 + 右侧详情抽屉 |
| 双击节点 | 以该节点为中心重开图谱 |
| 悬停节点 | 圆点外扩 1.5 倍 + 相连边 opacity 提到 0.85 |

## 7. 明确禁止（参考图里没有的东西）

- 球体 `SphereGeometry` + `MeshStandardMaterial`
- 光晕 `Sprite`（`makeGlowTexture`）
- 选中 `TorusGeometry` 环
- 贝塞尔曲线 `QuadraticBezierCurve3`
- 虚线 `LineDashedMaterial`
- 箭头 `ConeGeometry`
- 星尘 `Points`（`starfield`）
- 场景雾 `FogExp2`
- 标签白底圆角块
- 图谱容器边框 / 圆角 / 阴影 / 网格
- 多色边常驻显示

## 附：采样脚本

```python
from PIL import Image
import numpy as np
from scipy import ndimage

im = np.asarray(Image.open(PATH).convert('RGB')).astype(int)
reg = im[380:920, 40:840]
lum = reg.mean(axis=2)
lab, n = ndimage.label(lum < 150, structure=np.ones((3, 3)))
sizes = ndimage.sum(lum < 150, lab, range(1, n + 1))
for i in np.argsort(sizes)[::-1][:14]:
    ys, xs = np.nonzero(lab == i + 1)
    sub = reg[ys, xs]
    dark = sub[np.argsort(sub.mean(axis=1))[:max(1, len(sub) // 10)]]
    print(ys.min() + 380, ys.max() + 380, xs.min() + 40, xs.max() + 40,
          '#{:02x}{:02x}{:02x}'.format(*dark.mean(axis=0).astype(int)))
```
