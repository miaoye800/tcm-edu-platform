# 知识图谱页面改版方案

> 结论先行：现在的图谱不是"设计不够高级"，而是**拿不到真实数据**。视觉层已经做了 3D、光晕、关系配色、证据卡，工程量不小；真正拖后腿的是数据链路和交互深度。

---

## 一、现状诊断（均有代码与数据证据）

### 1.1 数据链路：三条路，只有一条通

| 链路 | 状态 | 证据 |
| --- | --- | --- |
| 学习页生成资源 → `learning.resources.graph.payload` → AtlasView | 通 | `frontend/src/views/AtlasView.vue:12` |
| `GraphAgent` → `graph_cache` → 前端读取 | **断** | 后端只有 `/api/graph/node/{id}/detail` 与 `/api/graph/default-center`，前端 `services/graphApi.ts` 只调了前者，后者零调用 |
| payload 为空 → `mockMahuangGraph` | 兜底 | `frontend/src/stores/graph.ts:6-54`，15 个节点硬编码麻黄 |

实测生产库 `backend/.data/qihuang.db`：

```
knowledge_node      175
graph_entity          0
herb_relation         0
graph_cache           0
graph_detail_cache    0
```

知识库有 75 味药（`backend/data/herbs/*.json`，10 个分类），但图谱侧三张关系表是空的。

**直接访问 `/atlas` 时看到的是硬编码的麻黄图，不是真实数据。**

### 1.2 布局算法：不是力导向，是"套球壳"

`GraphView.vue:198-218` 的 `nodePositions()`：

1. 从 `center_id` 做 BFS 分层；
2. 同层节点按斐波那契球面均匀撒在一个球面上，半径 = `125 + (level-1)*95 + sqrt(层大小)*17`。

结果：同层节点彼此不排斥，密度一高就重叠；层级关系被"距离"表达，但球面透视会误导；相机自动旋转时，背面标签被球体自身遮挡。

### 1.3 交互缺口

| 能力 | 现状 |
| --- | --- |
| 搜索定位 | 无 |
| 多跳展开 | 只有"以某节点为中心"重置整图（`expand`） |
| 路径查询 | 无（中医"药—证—方"链路天然适合做最短路径） |
| 悬停高亮邻接 | 有（会整图重建，有性能开销） |
| 筛选联动 | 有实体/关系筛选，但无计数、无"仅看已选" |
| 移动端 | 3D 画布 635px 固定高度，触控手势与页面滚动冲突 |

### 1.4 学习闭环缺失

详情面板（`GraphView.vue:53-74`）展示性味归经、功效、剂量、禁忌、出处，但：

- 不告诉用户"这个节点在你的学习路径上处于哪一步"；
- 关联考点只显示一个百分比（`关联考点.exam_frequency`），没有"考什么、怎么考"；
- 没有"下一步学什么"的推荐。

## 二、可参考的三个设计范式

### 范式 A：局部图 + 深度控制（Obsidian Graph View / InfraNodus）

- 只显示当前节点 N 跳以内的邻居，默认 2 跳；
- 节点大小 = 连接度（不是层级），一眼看出"枢纽药"；
- 悬停时邻接边加亮、其余淡到 15%；
- 拖拽可固定节点位置，布局记住用户调整。

**借鉴点**：把"跳数"做成显式控件，解决 60 节点上限的信息丢失问题；节点大小改为度数编码。

### 范式 B：搜索式探索（Neo4j Bloom / Kumu）

- 顶部一个搜索框，输入实体名 → 定位并聚焦；
- 点击节点"展开邻居"（增量加入，不重置视图）；
- 右侧属性面板分 Tab：概览 / 关系 / 出处；
- Kumu 的 "story" 模式：把若干节点+视角变化串成一条讲解动线。

**借鉴点**：搜索框 + 增量展开，是"实用"与"炫技"的分水岭；story 模式可直接用于课堂演示。

### 范式 C：路径地图（Duolingo path / 技能树）

- 主线是线性关卡，图谱作为"支线探索"入口；
- 当前进度高亮，已完成节点置灰打勾；
- 每个节点有"预计耗时/难度"。

**借鉴点**：图谱页底部加一条"当前学习路径"进度条，把图谱接回学习闭环。

### 推荐组合

**默认 2D 局部图（A）+ 搜索与增量展开（B）+ 路径进度条（C）**，3D 降级为可切换的"全景模式"。

理由：3D 球面在"看关系"这件事上是负收益——透视遮挡、深度歧义、移动端性能。3D 适合做首次进入的 3 秒惊艳动画，不适合作为主视图。

## 三、改版方案

### 3.1 页面结构（左中右三栏）

```
┌──────────────────────────────────────────────────────────────┐
│ 搜索框（药/证/方，支持拼音首字母）   [局部视图|全景] [2跳▾]   │
├────────┬────────────────────────────────────┬────────────────┤
│ 实体   │                                    │ 节点详情        │
│ 药材 12│          力导向画布                 │ 麻黄            │
│ 证候  4│      （Canvas 2D，可平移缩放）       │ 性味归经…       │
│ 方剂  3│                                    │ ── 概览/关系/出处│
│ 类属  2│                                    │ 高频考点 92%    │
│        │                                    │ ┌────────────┐ │
│ 关系   │                                    │ │ 问一句      │ │
│ 协同 ──│                                    │ └────────────┘ │
│ 禁忌 --│                                    │                │
├────────┴────────────────────────────────────┴────────────────┤
│ 当前学习路径：解表药 · 第 3/20 味        以此为起点继续学 →   │
└──────────────────────────────────────────────────────────────┘
```

### 3.2 视觉方向

保留现有国风设计语言（`--qh-graph-*` 变量体系完整，不必推翻），但做三处调整：

1. **去掉星空与球面**：改成宣纸底纹 + 淡墨经络线，更贴中医主题，也省 GPU；
2. **节点改"印章 + 药名"**：药材用圆形墨点，方剂用方形（"方"有方正之意），证候用菱形，类属用浅灰小点——形状编码比颜色更抗色盲；
3. **关系线降噪**：默认只画强关系（confidence ≥ 0.85），弱关系在悬停时淡入。

### 3.3 交互清单（按优先级）

**P0（不做就等于没改）**

- [ ] 补 `/api/graph/{center_id}` 读接口，前端优先读缓存图，mock 只作为离线演示
- [ ] 启动时调 `/api/graph/default-center`，用当前学习节点作为中心
- [ ] 顶部搜索框（药名/别名/证候/方名，模糊匹配）
- [ ] 点击节点：邻居径向重排 + 其余淡出（现在只是变色）
- [ ] 详情面板分 Tab，关系列表可点击跳转

**P1（决定"好不好用"）**

- [ ] 跳数控件（1/2/3 跳），替代 60 节点硬截断
- [ ] 双击节点增量展开邻居（保留已有视图，不重置）
- [ ] 两点最短路径查询（"麻黄 → 小青龙汤 怎么连上的"）
- [ ] 左侧筛选带计数，选中项才显示
- [ ] 底部学习路径进度条

**P2（加分项）**

- [ ] 图谱内提问（接 RAG，见第四节）
- [ ] 课堂演示 story 模式：预设 5-8 个视角，按顺序讲解
- [ ] 3D 全景模式保留为切换项，默认关闭自动旋转

### 3.4 技术选型

| 需求 | 建议 | 理由 |
| --- | --- | --- |
| 2D 力导向布局 | `d3-force`（charge/link/collide/center） | 成熟、可控、可固定节点 |
| 渲染 | Canvas 2D 自绘（≤300 节点） | 现有代码已是手绘 three 场景，改造成本低；DOM 方案在 300 节点会卡 |
| 大规模（>1000） | `sigma.js` 或 `cosmos.gl` | WebGL，但当前数据量用不上 |
| 标签 | Canvas 绘制 + LOD | 缩放到阈值才显示文字，避免重叠 |
| 3D 全景 | 保留现有 three 实现 | 已能跑，作为可选模式 |

数据量测算：75 味药，若每味平均 8 条关系，全图约 300 节点 / 600 边。这个量级 Canvas 2D 完全够，**不需要引入 WebGL 图谱库**。

### 3.5 数据层改造（关键）

现在 `GraphAgent.generate()` 是"按中心节点生成 + 缓存"，适合单点展开，不适合全图。

建议补一个离线预计算任务：

```
scripts/build_graph.py
  ├─ 遍历 data/herbs/*.json 全部 75 味
  ├─ 复用 graph_intelligence._rule_relations（规则层，不调 LLM）
  ├─ 写入 herb_relation（当前 0 行 → 预计 500-800 行）
  ├─ 生成全图快照 graph_cache['__global__']
  └─ 计算并缓存每个节点的 1/2 跳邻接表（前端展开用）
```

这样：全图秒开、单点展开秒开、零 token、可复现。LLM 只在"解释"环节出现。

## 四、RAG 现状：有，但图谱没用上

### 4.1 已有的 RAG 能力（完整可用）

| 模块 | 作用 |
| --- | --- |
| `backend/app/kb/embedding.py` | 智谱 `embedding-3`，无 Key 时用确定性 mock 向量（中文 2-4 gram 哈希） |
| `backend/app/kb/retriever.py` | Chroma 向量检索 + 分数阈值 + 概念级 mock 语义兜底 |
| `backend/app/kb/ingest.py` | 75 味药入库，字段含功效/主治/配伍/鉴别/十八反 |
| `backend/app/kb/validate.py` | 知识库校验 |
| `backend/app/agents/graph.py` | LangGraph 主图：`router → rag_agent → explain_agent`，带 trace 与 sources |

### 4.2 图谱侧为什么没接

- 节点详情走 `backend/app/agents/graph_details.py`：直接读 JSON 知识库字段，**不走向量检索**；
- 图谱结构走 `GraphAgent`：规则抽取 + 可选 LLM 增强，一次生成后落 `graph_cache`；
- 前端没有任何"提问"入口。

也就是说：**RAG 在"对话答疑"链路上是通的，在"图谱"链路上是断的。**

### 4.3 建议接入的三个 RAG 场景

1. **图谱内提问**：选中节点后问"麻黄为什么配桂枝"，检索范围限定在该节点 2 跳邻居对应的知识库条目，回答必须带 `sources`；
2. **跨节点对比**：同时选中两味药 → 检索二者功效/性味/主治 → 生成对比表（差异项高亮）；
3. **按证候反查**：选中证候 → 检索所有主治该证候的药材 → 图谱高亮。

第 1 项性价比最高，复用现成 `search()`，只需加一层 `center_id` 邻域过滤。

## 五、图谱该用 Agent 还是本地固化？

### 结论：分层，不是二选一

| 层 | 做法 | 理由 |
| --- | --- | --- |
| **结构层**（节点、边、证据、置信度） | **离线固化** | 配伍禁忌错一次就是教学事故；LLM 输出不可复现、不可审计、每次要花钱；图谱要能离线演示 |
| **交互层**（解释、追问、对比、学习建议） | **在线 Agent + RAG** | 用户问题开放，无法预生成；有出处可校验 |
| **扩展层**（点击展开邻居） | **固化邻接表 + 阈值过滤** | 秒开，不需要推理 |

### 什么时候才该让 Agent 生成结构

只有一种情况：**新增药材入库**，需要为它自动发现关系。这时也应该走：

```
LLM 生成候选关系 → 规则校验（关系类型白名单、双向一致性、来源必须存在）
→ 置信度打分 → 落入 herb_relation（标记 pending）
→ 人工/抽样复核后转 approved
```

绝不能"LLM 直接写库、前端直接显示"。

### 判断标准（可复用）

| 问题 | 用 Agent | 用固化 |
| --- | --- | --- |
| 答案需要唯一且可审计？ | ✗ | ✓ |
| 同一输入要稳定复现？ | ✗ | ✓ |
| 需要离线/断网可用？ | ✗ | ✓ |
| 每次调用成本敏感？ | ✗ | ✓ |
| 问题开放、无法枚举？ | ✓ | ✗ |
| 需要多步推理与工具调用？ | ✓ | ✗ |

图谱结构 = 前四行全中；图谱问答 = 后两行全中。
