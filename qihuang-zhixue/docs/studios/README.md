# 三个资源工坊 · 总览

> 读者：实现者与评审者。
> 分册：`ppt.md`（幻灯）、`mindmap.md`（思维导图）、`doc.md`（文档）、`assets.md`（素材管线）。
> 本文只讲三者的**共同部分**；任一工坊的具体做法在分册里，出现重复即视为结构不当。

---

## 1. 定位与边界

三个工坊（幻灯、导图、文档）是**对外可调用的资源生成能力**：调用方给出一个需求包，拿到一个 artifact——

```
resource_id + open_url + stream_url + evidence（三档来源）+ verify（校验报告）
```

内部是**有限的规划与检查步骤**，不是可自由调工具、可自造步骤、可跳过确认的自主 Agent。

与对话 Agent 的分工：对话 Agent 负责把用户的话变成需求包并选择能力；工坊把需求包变成可检查的成品。工坊**不反问用户**，唯一例外是 G0 的关键歧义（见 §3.2）。

---

## 2. 统一能力形状（8 步）

```
需求包：query / audience / materials / node_id / params / client_invocation_id
1 understand  理解主题与受众   → 主题理解、受众假设、可核对的原话
2 assess      判断材料缺失     → 知识覆盖 + 素材覆盖 + 缺口清单
3 plan        规划结构         → 方案（页 / 节 / 支）
4 design      设计呈现         → 版式 / 结构 / 体裁与视觉约束、素材槽位需求   ★本版新增
---- G1 确认闸门：结构与设计一次确认，确认后才生成 ----
5 select      资源选型         ← 三工坊在此分道
6 compose     按单元生成       → 逐页 / 逐支 / 逐节
7 check       校验             → 结构、容量、依据、设计合规、资产合规
8 deliver     artifact         → resource_id + open_url + stream_url + evidence + verify
```

相比上一版，只有一处结构性改动：**`design` 成为独立一步，且与 `plan` 同批确认**。

理由：`plan` 回答「讲什么」，`design` 回答「长什么样」；两者共同构成用户能判断的「施工图」。若把设计塞进 plan 或塞进 compose 的提示词，用户无法在生成前看到它，模型也无法在生成时稳定遵守它——这正是当前"确认完又回到固定模板"的根因。

### 2.1 「有限」的可执行含义

不是口号，是四条可断言：

1. 每一步的取值只能在**枚举集合**里选：版式 10 种、导图结构 4 种、块类型 16 种、字号 7 级、密度 3 档、槽位 4 类。
2. 不能自造步骤、不能在步骤内自由调工具、不能跳过 G1。
3. 单步失败的重试范围限于该单元（页 / 支 / 节），不重跑整份。
4. 每次调用必须产出可核对的 `evidence` 与 `verify`，否则不算交付。

## 3. 两处闸门

### 3.1 G1 确认闸门（已有，扩为「结构 + 设计」）

- `POST /api/resource/tasks/{id}/plan/confirm` 接受 `{plan, design}`，两者同批落 `meta.confirmed_plan` / `meta.confirmed_design`。
- `POST /api/resource/tasks/{id}/plan/revise` 接受文本反馈或 design patch；修订后**整份重排重展示**，不在原方案旁加备注。
- 确认后 `compose` 只读 `confirmed_plan + confirmed_design`，不得回落模板。
- 现状：plan 闸门已通（`backend/app/resources/service.py:688-713`），前端确认面板已三工坊共用（`frontend/src/components/resources/PlanReview.vue`），缺的只是 design 这一段载荷。

### 3.2 G0 关键歧义闸门（新增）

只在「缺项会显著改变方案」时触发，规则：

- 最多**一问**，必须附 3–4 个候选（取自知识库覆盖度高的实体）+ 一个「你帮我选」。
- 用户选「帮我选」→ 取候选首条继续，并把该选择写进 `design.assumptions`。
- 受众、时长、篇幅这类偏好**不追问**，按默认值走并写明假设。

反例（现状）：`PptParams.parse` 在用户没说受众时静默填「中医药专业本科生」（`backend/app/ppt/params.py:39`），方案里也不写这个假设，用户拿到成品才发现对象错了。

## 4. 三工坊分道表

| | plan 单元 | design 内容 | select 内容 | compose 粒度 | check 重点 | 用素材 |
|---|---|---|---|---|---|---|
| 幻灯 | 页 | 版式原型 + 视觉主题 + 密度 + 槽位 | 版式 + 图形语法 + 资产 | 页（含页内 check→定向重写） | 容量 / 溢出 / 依据 / 许可 / 装帧预算 | 是（证据位 + 装饰位） |
| 导图 | 支 | 结构 + 主题 + 视觉语法（节点形 / 连线 / 层级色）+ 折叠策略 | 骨架 + 主题 + 图标词表 | 支 | 结构折叠 / 父子语义 / 来源档位 | 否（明确不做位图） |
| 文档 | 节 | 体裁版式 + 块编排 + 引用体例 + 图表策略 | 块类型 + 引文片段 + 图表 | 节 | 章节覆盖 / 引文支持 / 篇幅 / 重复 | 仅图表，不含配图 |

差异必须落在数据上，不能只换动词：

- **幻灯**的 `design` 是"这一页用什么版式、什么密度、哪几个槽位填什么"。它是三者中唯一有「设计语言层 + 素材槽」的工坊，也是唯一需要外部资产的。
- **导图**的 `design` 不是"好不好看"，而是把结构的 maxDepth / 分支预算写进 `shape` 步，让结构真正参与生成。现状 `structure` 只写进 meta 与渲染，生成侧从不读它（`backend/app/mindmap/agent.py` 只读 `params["confirmed_plan"]`），所以"四面发散"的左右分布与生成内容无关。
- **文档**的 `design` 要把体裁从关键词规则（`backend/app/docs/agent.py:47-89`）提到用户可确认的位置，并把写死的「总长 1200-2500 字」（`backend/app/docs/prompts.py:55`/`:74`）变成可配置目标。

## 6. 知识来源三档 × 素材槽位两类

这是两个正交维度，必须分开，否则会出现"把 AI 生成图标成教材依据"这类错误。

### 6.1 文本依据三档（对外）

| 对外档位 | 含义 | 内部 `origin` 细分 |
|---|---|---|
| `knowledge_base` | 教材、图谱、结构化数据 | `textbook` / `graph` / `structured` |
| `user_material` | 用户带来的材料 | `user` |
| `model` | 模型补充，无可核出处 | `model` |

现状两套词表分叉：方案层用 `knowledge_base/user_material/model`（`planning.py:38-45`），导图节点层用 `textbook/graph/model`（`mindmap/evidence.py:38-40`）。统一口径：**对外只报三档，内部 `origin` 可下钻**；`graph` 是 `knowledge_base` 的细分，不是第四档。

### 6.2 素材槽位两类（硬约束）

| 槽位类别 | 允许来源 | 可否生成 | 页面角标 |
|---|---|---|---|
| `evidence`（证据位） | 教材 / 图谱 / 用户材料 / PD 实拍，必须带出处 | **绝不** | 显示具体出处 |
| `decorative`（装饰位 / 点题位） | 参数化母题 / 公版图谱 / 生成图 | 可，≤3 张/份，须标注 | 生成图标「AI 生成示意」；平替标「示意」 |

缺图时的正确行为是**空着并进 `gaps`**，不是拿生成图或风格插图顶上。规则能证明"引用索引有效"，不能证明"这张图画的就是这味药"——所以证据位宁缺毋滥。

实现中修订的三处判断，写在这里是为了避免下一轮再讨论一遍：

1. **页标题用字号阶梯第三级（3.2），不是第二级（4.6）**。40 字标题在 4.6 下要折三行，版心被正文挤掉；4.6 留给章节页的巨号标题。`frameFor` 已改。
2. **标题断行只允许落在标点后**。中文默认「任意两字之间可断」，「人参：补气第一药」会断成「补 / 气第一药」；`SlideSurface` 在标点后插零宽空格并配 `word-break: keep-all`。
3. **`evidence` / `figure` 槽位永不走参数化母题**（`select._parametric` 直接返回空串）。母题是构图元素（底纹/角饰/界格/印章），不是「这味药长什么样」；硬顶上去就是拿风格插图冒充证据。
4. **槽位类别只锁一个方向**：`evidence` 位拒绝装饰图，但证据图可以进 `figure` 位当配图。原来要求两边严格相等，结果「主要功效」页想配一张药材照永远落空——图在库里、槽位在页上，就是接不上。反过来这一条不能松：生成图再好看也不能进证据位。
5. **角花是「外框 + 内花」两段结构，不是一根藤**。一根藤有方向有起止，镜像到四角就是四条杂草；外框（距边两道平行线 + 转角方胜）给「角」的身份，内花（卷草/折枝/竹叶/回纹/缠枝）给手写的温度。五款共用同一套外框（`cornerFrame`），`frame=0` 时只留内花给正文页那种放不下界栏的角落。

导出的取舍：pptx 含图位、不含纸纹与角饰。图是内容，纸纹是装饰——母题是 SVG，转图才能进 pptx，会让十几页的稿从几十 KB 涨到几 MB，而放映时那层淡纹几乎看不见。**屏幕更雅、导出更轻**是刻意的，不是遗漏；要改先改这条。

### 7.2 M1：不固定版式，让模型自己设计

S1 那一期的实现是「十种版式原型 × 写死的几何」。跑出来十二页里八九页一个样，因为模型只能从十个里挑一个，挑完几何不是它的。M1 把这一层拆成两件事：

| 谁定 | 定什么 | 在哪 |
|---|---|---|
| 模型 | 信息结构（`purpose` / `blocks`） | 参与校验与降级 |
| 模型 | 视觉方案（`scene`：图层、坐标、字号、竖排、角花、印章） | `ppt/scene.py` |
| 代码 | 按基元画，**不认识任何版式** | `SceneSurface.vue` / `pptxExport.ts` |

配套三件事：素材改成**工具循环**（模型自己搜、看、绑、生成，§`ppt.md` 3.5.1）、渠道成册供它查（`channels.py`）、远程素材钉 URL 走代理（§`assets.md` 5.7）。

模型写场景这一步是 `scene_art.paint_scenes()`：逐页一次调用，校验不过把违反的那一条回灌一次，再不过退回兜底。**没有这一步，场景就只是兜底生成器的另一个名字**——十二页仍会长得像，只是换了个字段名。规则见 `ppt.md` §3.4.1。

这一步的代价要认清：不确定性从"选哪个模板"变成"它自己画的这页好不好看"。所以兜底必须是**可预测**的（`scene_fallback.py`），而模板库那种"可选的好版式"反而收走设计权——两者不是一回事。

## 8. 验收矩阵

不以「JSON 合法」或「成功生成」为质量标准。五个维度，各自给判定方法：

| 维度 | 判定方法 | 通过线 |
|---|---|---|
| 需求响应度 | 方案单元 ↔ 用户明确要求逐条对照；G0 的假设是否写明 | 用户明确提出的项 100% 有落点 |
| 结构适配度 | 页序 ↔ 方案对应率；purpose 与 blocks 一致性 | 对应率 ≥90%，无自造页 |
| 来源可信度 | 三档计数；证据位是否绑定可核出处；`model` 是否被误标 | 误标 0 条 |
| 修订遵从度 | 确认后成品 vs 确认方案 diff | 无方向性偏离（模板回流即不通过） |
| 视觉一致性 | 截图基线 diff、字号越阶数、装饰预算超限数 | 基线 diff < 阈值；越阶 0 |

判定手段：人工评审（基准页）+ 截图 diff（`frontend/deliverables/mindmap-baseline` 已有先例）+ 契约测试（pytest）。

## 9. 明确不做

1. **不合并为单一生成器**：三者的 select/compose/check 内容不同，合并只会得到一个什么都能调、什么都不精的 Agent。
2. **不把工坊包装成"全程自主 Agent"**：8 步形状、两处闸门、逐页 compose 都由代码控制流程，模型不做下一步决策。唯一的例外是**素材取用**这一步——那里它确实在动手（搜、看、绑、生成），因为"哪张图配得上这页"没法用字符串匹配决定。边界由代码给（渠道白名单、证据位硬约束、预算），不是靠它自觉。
3. **不承诺知识库覆盖所有主题**：451 味药之外的题，走 `model` 档并标注。
4. **不在运行时把素材写进仓库**：本地库开发期采集、运行期只读；远程渠道生成期按需检索但**只钉 URL 不下载**（`assets.md` §5.7）。落盘的只有自己的生成图。
5. **不无限制生图**：已接通（`qwen-image-2.1-pro`），但每稿 ≤3 张、只进装饰位、必须落盘并记 `prompt/model`。
6. **不做导图配图**：导图的视觉语法是结构与连线，不是插图。
